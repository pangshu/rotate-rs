# 2026-10-13

## 排查（仅分析，未改代码）：归档名恒带 `.1`，但并无同秒重名

用户现象：`E:\work\rust\PilotCms\logs` 下 18 个归档**全部**是
`app.<date>.1.log`，没有任何 `.2/.3`，时间戳两两不同（无同秒重名）。

期望语义：正常轮转 → `app.<date>.log`；只有同秒重名冲突时才出现 `.1`。

### 根因（一句话）
`{counter}` 在本库是**必填段**、且初值恒为 1 —— 第一次候选名天然就是 `.1`，
与"是否重名"无关。

证据链：
1. `core-rs/src/observability/logging.rs:168` 传入模板
   `{dir}/{name}{sep}{date}{sep}{counter}{sep}{suffix}`（= rotate-rs 默认模板）。
2. `src/engine.rs:261` `let mut counter: u32 = 1;`，循环第一次就
   `render(&known, &date, Some(counter))`。
3. `src/naming.rs:176-180` `Slot::Counter` 只要 `Some(c)` 就无条件写数字，
   没有"值为 1 则省略"的逻辑。
4. `date` 精确到秒且本次两两不同 → `create_new` 第一次即成功 →
   `counter += 1`（AlreadyExists 分支）**从未执行**。故全是 `.1`。
5. 目录实测：无 `.2+`、无同秒重复 → 冲突分支未触发，`.1` 纯属初值产物。

### 设计语义差异
- 现状：counter = "归档序号"（必带，从 1 起）。
- 期望：counter = "重名去重后缀"（可选，冲突才补）。
- core-rs 配置注释里的"`<时间>.<序号>`"印证了"序号"这一原始设计意图，
  即库按自身设计工作，是**期望与设计不一致**，非实现 bug。

### 要达到期望行为需动的点（未实施）
1. `engine.rs`：候选序列改为 `None → Some(1) → Some(2)…`（counter 起始值 + 循环）。
2. `naming.rs::render`：counter 为 None 时不能只跳过数字，**还必须跳过其前面的
   `{sep}`**，否则渲染成 `app.<date>..log`（双点）。现有"末尾 suffix 为空剥离
   `{sep}`"是同类的特殊处理，可参照（或把 `{sep}{counter}` 视作一个可选组）。
3. `naming.rs::parse`：**当前 `app.<date>.log` 解析不出来**（模板要求 date 后是
   `.`+数字+`.`+suffix，而 `.log` 只有一个点）→ 必须让 counter 可缺省，
   产出 `counter=None`、`rotation_key=date`。
   ⚠️ 若不改 parse：新命名的归档会被 `scan_dir` 跳过 → `max_backups` 清理与
   `compress` 补压**静默失效**（与 10-08 记录里"模板尾部点被 Windows 剥离"
   导致失效是同一类坑）。
4. `engine.rs:312` `last_rotation_key`：无 counter 时用纯 `date`，与 parse 保持一致。
5. 兼容性：已有 `app.<date>.1.log` 仍按旧规则解析（counter=Some(1)），历史文件不受影响。

### 备注
- 同秒冲突在当前配置（`interval_secs=5`，date 秒级）下很罕见，仅当
  interval < 1s、size 阈值极小，或同目录多 Writer（10-08 修掉的 core-rs 双 init）时出现。
  改成期望语义后，绝大多数归档将变成无序号名。
- 用户明确要求"先别修改代码"，本次仅出分析结论。

## 实施记录（同日，用户确认后落地）

目标：`{counter}` 由"必带归档序号"改为"重名去重后缀"——
同 date 首次轮转 `app.<date>.log`，重名才补 `.1/.2`。

### 改动
- `src/naming.rs`
  - `Template` 新增 `slots_optional: Option<Vec<Slot>>`，编译期由
    `counter_optional_variant()` 生成"缺省 counter"槽序列（移除首个 `{counter}`，
    且若其紧邻前槽是 `{sep}` 一并移除）。
  - `render`：`counter == None` 时 `{counter}` 渲染为空，并**回退掉紧邻的前一个
    `{sep}`**（否则双点 `app.<date>..log`）。带 `i>0 && slots[i-1]==Sep &&
    !sep.is_empty() && s.ends_with(sep)` 守卫。
  - `parse`：抽出 `match_slots()`（回溯 + date 后置校验 + suffix 为空的补分隔符重试），
    先按带 counter 形态匹配（保证 `.1.log` 的 date/counter 切分正确），失败再按
    `slots_optional` 匹配无序号名；抽出 `strip_head()` 供两形态共用。
  - 新增 7 个单元测试（渲染省略、双形态解析、渲染↔解析往返、非本库文件拒绝、
    无 counter 模板、空 suffix、counter 前为字面量）。
- `src/engine.rs`
  - 候选序列由 `1,2,3…` 改为 `None → Some(1) → Some(2)…`；
    新增自由函数 `next_counter()`（`None` 且模板无 `{counter}` → 报错，保留规则 5）。
  - `last_rotation_key` 改为按 `Option<u32>` 组合（无序号时即 `date`），
    与 `parse` 的 `rotation_key` 规则对齐。
- `src/config.rs` / `src/lib.rs` / `README.md`：补充 `{counter}` 语义说明（新增使用约束第 7 条）。
- `tests/rotation.rs`：新增 2 个集成测试
  - `archive_name_has_no_counter_until_collision`：Size(1) + 分钟精度 date，
    确定性构造"同 date 重名" → 断言产出 `app.<date>.log` 与 `app.<date>.1.log`。
  - `max_backups_cleans_counterless_archives`：回归守卫，证明无序号归档仍能被
    scan 识别、`max_backups` 清理不静默失效。

### 验证
- `cargo test`：7 单元 + 6 集成 + 1 doctest 全绿。
- **回归有效性**：`git stash push src/engine.rs src/naming.rs` 后跑新集成测试 →
  2 个新测试均 FAILED（旧行为产出 `app.<date>.2.1.log`），确认是真回归守卫。
- **历史兼容**：临时探针（跑完已删）解析 `PilotCms/logs` 真实目录 18 个归档 →
  全部 OK（`counter=Some(1)`），`.gitkeep` 正确拒绝。
- `cargo clippy --all-targets`：仅 2 条既有警告（`fetch_update` deprecation、
  测试里的 `&PathBuf`），与基线一致。
- `cargo fmt --check`：`naming.rs` 已无差异；剩余 `channel/compress/config/engine.rs`
  为**既有 import 排序差异**（基线如此，未触碰）。

### 影响与注意
- 改动后绝大多数归档将变为无序号名（`interval_secs=5`、秒级 date 下同秒冲突极罕见）。
- core-rs / PilotCms 侧**无需改代码**：模板字符串不变，语义在库内实现。
  `PilotCms/.workbuddy-ai/backup-config-toml/default.toml` 里"`<时间>.<序号>`"的旧注释
  属备份文件，未动。
