## rotate-rs：Hybrid 模式"同一秒出现 .1/.2 两个空文件"排查

用户报告（未改代码，仅分析）：Hybrid 模式、每 10s 切割时，出现 `app.<date>.2.log`，
以及 `app.2026-10-08-22-15-36.1.log` 与 `.2.log` 两个**空文件同秒**。

### 结论（已用临时 example 复现，跑完删除，仓库保持干净）
1. 命名规则 `{dir}/{name}{sep}{date}{sep}{counter}{sep}{suffix}`，`{date}` 为
   `%Y-%m-%d-%H-%M-%S`（**秒级精度**）。engine.rs 轮转时用 `create_new` 占位探测，
   同名冲突则 counter++ → 因此"**同一秒内发生 ≥2 次轮转**"必然产生 `.1/.2/.3`。
   `.2` 不是命名 bug，而是"同秒双轮转"的必然结果。
2. **空文件**：rotate_inner 不做"活跃文件为空则跳过"的判断；NonBlocking 的定时器
   在空闲时仍按周期触发轮转 → 把 0 字节的活跃文件归档成空文件。
3. 复现证据（interval 缩短以加速）：
   - 单实例 空闲 + interval=100ms：22:21:55 出现 .1/.2/.3，56 出现 .1~.5，全部 0B。
   - **多实例**（同目录 2~3 个 Writer）：空闲时同秒 `.1/.2`（0B）；写入时同秒
     `.1(144B)/.2(160B)` —— 与用户现象完全一致。
   - max_size 很小（300B）时：每秒多次 size 轮转 → 同秒 .1/.2/.3（但文件非空）。

### 附带发现的两个独立 bug
- **时间轮转周期≈配置值的 2 倍**：channel.rs 超时分支用旧 deadline `+= iv` 推进，
  而 `last_rotation` 在轮转完成时才置为 now（晚于 deadline）→ 下一次超时
  `elapsed = iv - ε < iv` 被跳过，实际隔一个周期才轮转。实测 interval=1s → 2s 一次。
- **空文件归档**：应跳过 `current_size == 0` 的轮转（只重置定时器）。

### 待用户确认
实际 interval 取值、是否单实例、max_size 是否真的未达、写入模式（Sync/NonBlocking）。

### 真因：`logging::init` 同进程被调用两次，每次都真的 `rotate_rs::open()`
调用链：
- `PilotCms/src/main.rs:31` → `logging::init(&settings.fw)`（第 1 次）
- `main.rs:50 App::bootstrap()` → `core-rs/src/app.rs:102` → `state.rs:107 bootstrap()`
  → `state.rs:112 bootstrap_in` → `state.rs:125 from_settings` → **`state.rs:141 logging::init`（第 2 次）**

`logging.rs:167 init()` 中 `build_rotating_writer()`（→ `rotate_rs::open`）**无条件执行**，
"幂等"只覆盖 `mount()`（`set_global_default` 失败即 no-op）。故第 2 次 init 再建一套 Writer，
两套都被 `LogGuard._file` 保活 → **同目录两个 worker + 两个定时器**。
库 `lib.rs` 文档已声明"单进程独占日志目录，不支持同进程多实例"。

### 配置（PilotCms/config）
- `default.toml [log.file]`: `interval_secs = 5`, `max_size_mb = 100`, `max_backups = 30`,
  `non_blocking = true`, `rotation = "hybrid"`, `compress = false`（日志目录里 30 个归档与之吻合）
- `testing.toml`: `interval_secs = 10`, `max_size_mb = 1`, `max_backups = 5`
- 无 `.env`，未设 `RUST_LOG_FILE`

### 探针复现（临时 example，跑完已删）
- 双实例（同目录）→ 同秒 `app.<t>.1.log` + `app.<t>.2.log`（复现用户最初 22-15-36.1/.2）
- 单实例 interval=5s 空闲 27s → 归档在 10/20/30s，**实际周期 = 配置的 2 倍**，且全 0 字节
- `PilotCms/logs/app.log` 只有两条关机日志 → 应用全程空闲，故归档全空

### 建议修复（待用户确认后实施）
- **core-rs**：用 `static OnceLock<SharedRotatingWriter>` 包 `build_rotating_writer`，
  重复 init 复用同一 writer（修正注释里的"幂等"表述）。
- **rotate-rs**：① `rotate_inner` 入口 `current_size == 0 && self.file.is_some()` 时只
  `finish_rotation()` 直接返回（`file.is_some()` 不可省：`rotate_inner` 还兼作轮转失败后的
  恢复重试，file==None 时必须走恢复链，否则会短路恢复并误清 `last_rotation_error`）；
  ② 超时分支轮转成功后 `next_deadline = Instant::now() + iv`（修 2 倍周期）；
  ③ 可选：`Engine::new` 对活跃文件加独占，防多实例静默互踩。
